# AI GitGen

Git 변경 사항을 분석해 커밋 메시지와 Pull Request(PR) 제목·본문 초안을 생성하는 Python CLI 도구다. `git status`와 `git diff`에서 수집한 변경 내용을 프롬프트에 포함해 AI API에 전달하고, 응답을 정리·검증한 뒤 터미널에 출력한다.

이 도구는 커밋이나 PR을 자동으로 확정하지 않는다. 생성 결과는 초안이며, 사용자가 실제 변경 내용과 일치하는지 검토한 뒤 직접 적용해야 한다.

## 주요 기능

- **Git 변경 사항 수집**: 현재 저장소의 변경 파일과 diff를 입력 컨텍스트로 사용한다.
- **커밋 메시지 생성**: 변경 사항을 요약한 커밋 제목과 선택적 본문을 생성한다.
- **PR 초안 생성**: PR 제목과 `Why`, `What`, `How to Test` 섹션으로 구성된 본문을 생성한다.
- **출력 검증 및 정리**: 제목 길이와 PR 본문 구조를 검사하고, 응답에 포함된 불필요한 형식을 정리한다.
- **AI API 연동**: API 키를 환경변수로 관리하고, 모델과 생성 파라미터를 CLI 옵션으로 조정한다.
- **안전 모드**: diff에 포함될 수 있는 민감정보를 줄이기 위한 마스킹 또는 전송 제한 기능을 제공한다. 안전 모드가 모든 비밀정보를 탐지한다고 보장하지 않으므로 전송 전 diff를 직접 확인해야 한다.

## 개발 환경

- Python 3.10 이상
- Git이 설치되어 있고, 실행 대상 디렉터리가 Git 저장소로 초기화되어 있어야 한다.
- AI API 키와 해당 API를 사용할 수 있는 계정이 필요하다.

## 설치

### 1. 저장소 준비

프로젝트를 내려받거나 복제한 뒤 프로젝트 루트 디렉터리로 이동한다.

```bash
git clone <repository-url>
cd <repository-directory>
```

### 2. 가상환경 생성 및 활성화

macOS / Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Windows PowerShell:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
```

### 3. 패키지 설치

```bash
python -m pip install -r requirements.txt
```

## API 키 설정

API 키를 소스 코드에 직접 작성하거나 Git에 커밋하지 않는다. 현재 구현에서 사용하는 환경변수 이름은 `OPENAI_API_KEY`다.

## 사용 방법

명령은 Git 저장소의 루트 디렉터리에서 실행한다. 아래 예시는 프로젝트 진입점이 `main.py`인 경우를 기준으로 한다.

### 커밋 메시지 생성

```bash
python main.py commit
```

### PR 제목과 본문 초안 생성

```bash
python main.py pr
```

### 생성 파라미터 조정

CLI에서 지원하는 옵션은 `--help`로 확인한다.

```bash
python main.py commit --help
python main.py pr --help
```

모델, `temperature`, `max_tokens`는 생성 결과의 특성을 조정하는 옵션이다. 실제 옵션 이름과 기본값은 실행 시 `--help` 및 프로젝트의 `config.py`를 기준으로 확인한다. 예를 들어 구현에서 아래 옵션을 제공하는 경우 다음처럼 지정할 수 있다.

```bash
python main.py commit --model MODEL_NAME --temperature 0.3 --max-tokens 500
python main.py pr --model MODEL_NAME --temperature 0.3 --max-tokens 500
```

안전 모드 옵션이 해당 명령의 인자로 등록된 구현이라면 `--safe-mode`를 함께 사용할 수 있다. 지원 위치와 표기 방식은 `--help` 출력에 맞춰 사용한다.

```bash
python main.py commit --safe-mode
python main.py pr --safe-mode
```

> 명령어와 옵션은 현재 소스 코드의 `argparse` 설정이 기준이다. README 예시와 실제 `--help` 출력이 다르면 실제 CLI 구현을 우선한다.

## 실행 흐름과 모듈 설계

프로그램은 다음 흐름으로 동작한다.

1. **CLI 입력 처리**: 사용자의 `commit` 또는 `pr` 명령과 옵션을 읽는다.
2. **Git 변경 사항 수집**: Git 상태와 diff를 가져온다. 변경 사항이 없으면 안내 메시지를 출력하고 AI 요청을 진행하지 않는다.
3. **민감정보 처리**: 안전 모드가 활성화된 경우 구현된 마스킹·전송 제한 정책을 적용한다.
4. **프롬프트 구성**: 변경 내용과 커밋 또는 PR 출력 규칙을 결합해 AI 입력을 만든다.
5. **AI API 호출**: API 키와 생성 파라미터를 사용해 요청하고 응답 텍스트를 받는다.
6. **후처리 및 검증**: 불필요한 코드 펜스 등을 정리하고 제목 길이 및 PR 본문 구조를 검사한다.
7. **결과 출력**: 생성된 텍스트를 터미널에 표시한다. 실제 커밋 생성이나 원격 PR 등록은 수행하지 않는다.

디렉토리 구조와 주요 모듈의 책임은 다음과 같다. 

```
ai-gitgen/
│
├── main.py
│
├── src/
│   └── ai_gitgen/
│       ├── __init__.py
│       ├── cli.py
│       ├── config.py           # 기본 설정값 및 환경변수
│       │
│       ├── git_manager.py      # git status / git diff 수집
│       ├── ai_client.py        # AI API 호출
│       ├── prompt.py           # Commit / PR 프롬프트 설계
│       ├── validator.py        # 생성 결과 검증 및 후처리
│       └── safety.py           # safe-mode / 민감정보 마스킹
│
├── tests/
│
├── docs/
│   └── design.md
│
├── .env.example
├── .gitignore
├── README.md
├── requirements.txt
└── pyproject.toml
```

| 모듈 | 책임 |
|---|---|
| `main.py` | 프로그램 진입점 |
| `src/ai_gitgen/cli.py` | 명령과 옵션 처리, 전체 실행 흐름 제어, 결과 출력 |
| Git 수집 모듈 | `git status`, `git diff` 결과 수집 |
| `src/ai_gitgen/prompt.py` | 커밋·PR 생성 프롬프트 구성 |
| `src/ai_gitgen/ai_client.py` | API 키 확인, AI API 요청, 호출 오류 처리 |
| `src/ai_gitgen/validator.py` | 출력 정리 및 커밋·PR 형식 검증 |
| `src/ai_gitgen/config.py` | 기본 모델 및 생성 파라미터 관리 |
| 마스킹 모듈 | 안전 모드에서 민감정보 처리 |

### 수집·호출·프롬프트·검증을 분리한 이유

Git 수집 모듈은 외부 명령의 실행과 변경 내용 확보를 담당하고, AI 클라이언트는 API 요청과 응답 처리만 담당한다. 따라서 Git 명령 처리 방식과 API 제공자·요청 방식을 서로 독립적으로 수정할 수 있다. 두 모듈의 입력과 출력을 분리하면 Git 명령 결과를 고정한 단위 테스트와 API 호출을 대체한 테스트를 작성하기도 쉽다.

프롬프트와 후처리·검증도 별도의 책임으로 둔다. 프롬프트는 AI가 어떤 맥락과 형식으로 답해야 하는지를 지정하고, 후처리·검증은 실제 응답이 요구 형식을 만족하는지 확인한다. 프롬프트만으로 형식 준수를 보장할 수 없으므로 코드에서 검증 규칙을 다시 적용한다.

## 생성 파라미터

| 파라미터 | 의미와 영향 | 사용 시 참고 |
|---|---|---|
| `model` | 응답 생성에 사용할 AI 모델을 지정한다. 모델마다 품질, 속도, 비용 특성이 다를 수 있다. | 계정에서 사용 가능한 모델을 지정한다. |
| `temperature` | 생성 결과의 변동성에 영향을 준다. 낮은 값은 비교적 일관된 표현에, 높은 값은 다양한 표현에 유리할 수 있다. | 커밋 메시지처럼 일관성이 중요한 작업은 낮은 값부터 실험한다. |
| `max_tokens` | 생성 응답의 최대 토큰 수를 제한한다. | 너무 낮으면 본문이나 PR 섹션이 중간에 잘릴 수 있다. 필요한 출력 길이에 맞춰 조정한다. |

현재 기본값은 소스 코드의 `config.py`를 기준으로 한다. 종합 평가 당시 확인된 기본값은 `temperature=0.3`, `max_tokens=500`이다. 실제 코드를 변경했다면 해당 파일의 값을 확인해 문서와 일치시킨다.

옵션을 CLI에서 받도록 한 이유는 동일한 변경 사항에 대해 모델과 생성 설정을 바꿔 결과를 비교할 수 있도록 하기 위해서다. 다만 파라미터가 같아도 모델 응답이 항상 완전히 동일하다고 보장되지는 않는다. 결과를 비교할 때는 사용한 명령, 모델, 파라미터, 입력 diff를 함께 기록하는 것이 좋다.

## 출력 형식 및 검증 기준

- **커밋 제목**: 한 줄로 출력한다. 50자 이내를 권장하며 최대 72자를 기준으로 검사한다.
- **PR 제목**: 한 줄로 출력하며 최대 80자를 기준으로 검사한다.
- **PR 본문**: 다음 세 섹션을 포함하고, 각 섹션에 최소 한 개 이상의 불릿을 둔다.
  - `## Why`: 변경 배경과 목적
  - `## What`: 핵심 변경 사항
  - `## How to Test`: 테스트 방법
- **후처리**: 응답에 코드 펜스 등 불필요한 형식이 포함된 경우 정리한다.
- **검증 실패**: 생성 결과가 규칙을 만족하는지 확인하고, 문제가 있다면 직접 수정한다. 후처리는 문구의 사실관계나 기술적 정확성까지 보장하지 않는다.

### 커밋 메시지 출력 예시

아래는 출력 형식 예시이며, 실제 실행 결과가 아니다.

```text
--- Commit Message ---
feat: Git 변경 사항 기반 커밋 메시지 생성

- Git diff를 입력 컨텍스트로 전달
- 생성 결과의 제목 길이를 검증
----------------------
```

### PR 초안 출력 예시

아래는 출력 형식 예시이며, 실제 실행 결과가 아니다.

```text
--- PR Title ---
feat: 커밋 및 PR 초안 생성 기능 추가

--- PR Body ---
## Why
- 커밋 메시지와 PR 설명을 일관된 형식으로 작성하기 위해

## What
- Git 변경 사항을 AI 입력으로 전달
- 생성된 제목과 본문의 형식을 검증

## How to Test
- python main.py commit 실행
- python main.py pr 실행 후 섹션과 제목 길이 확인
----------------------
```

## 오류 처리 및 복구

| 상황 | 확인할 사항 |
|---|---|
| API 키가 설정되지 않음 | `OPENAI_API_KEY` 환경변수를 설정한 뒤 다시 실행한다. |
| 인증 실패 | 키의 유효성, 계정 권한, 사용 가능한 모델을 확인한다. |
| 네트워크 또는 API 요청 실패 | 네트워크와 API 상태를 확인한 뒤 필요하면 수동으로 재실행한다. |
| Git 저장소가 아니거나 Git 명령 실패 | Git 저장소 루트인지, Git이 설치되어 있는지 확인한다. |
| 변경 사항이 없음 | 파일을 수정하고 필요한 변경 사항을 스테이징한 뒤 다시 실행한다. |
| 생성 결과가 형식 검증을 통과하지 못함 | 출력 내용을 확인하고 직접 수정하거나 다시 생성한다. |
| 응답이 중간에 잘림 | `max_tokens`를 높이고 다시 실행한다. |

현재 구현은 API 호출 실패를 예외로 전달하는 방식으로 처리한다. 자동 재시도가 구현되어 있다고 가정하지 않는다. 실패 후 재실행하기 전 원인을 확인하고, 불필요한 반복 호출로 비용이 발생하지 않도록 한다.

## 민감정보 및 안전한 사용

`git diff`에는 소스 코드뿐 아니라 API 키, 토큰, 이메일 주소, 개인정보, 내부 URL 등의 정보가 포함될 수 있다. AI API에 전송하기 전에 다음을 확인한다.

1. `.env`, 비밀키, 인증 파일 등 민감정보가 변경 파일에 포함되지 않았는지 확인한다.
2. 안전 모드 옵션을 사용할 수 있다면 활성화한다.
3. 안전 모드의 마스킹·전송 제한 정책이 어떤 패턴과 범위를 처리하는지 소스 코드에서 확인한다.
4. 마스킹이 모든 종류의 비밀정보를 탐지하지 못할 수 있으므로, 전송할 diff를 직접 검토한다.
5. API 키를 소스 코드, README, 커밋 메시지, 로그에 기록하지 않는다.

안전 모드는 위험을 줄이는 보조 장치이지, 민감정보 전송을 완전히 방지하는 보안 경계가 아니다. 비밀정보가 포함된 변경 사항은 외부 API로 보내지 않는 것이 가장 안전하다.

## 비용 및 요청 횟수 관리

- `commit`과 `pr` 명령은 각각 필요한 결과를 생성하기 위해 실행한다. 같은 명령을 반복하면 API 사용량과 비용이 추가될 수 있다.
- 우선 기본 파라미터로 실행하고, 결과가 부족할 때만 `temperature` 또는 `max_tokens`를 조정한다.
- 변경 내용이 불필요하게 길면 전송 전에 diff를 검토한다.
- 모델별 가격과 계정 사용량 제한은 제공자의 최신 정책을 확인한다.
- 응답이 잘못되었다고 무조건 재요청하기보다, 간단한 형식 오류는 직접 수정하는 편이 효율적일 수 있다.

## 테스트 및 확인 방법

1. Git 저장소 루트에서 실행했는지 확인한다.
2. 변경 사항이 있는 상태에서 `commit`과 `pr` 명령을 각각 실행한다.
3. 변경 사항이 없는 상태에서 안내 메시지가 출력되고 API 요청이 생략되는지 확인한다.
4. API 키가 없는 경우와 잘못된 키·네트워크 오류 상황에서 오류 메시지가 표시되는지 확인한다.
5. 커밋 제목 및 PR 제목 길이, PR 섹션 헤더와 불릿 조건을 확인한다.
6. 안전 모드 사용 전후에 실제로 전송되는 입력 범위와 마스킹 결과를 확인한다.
7. 생성된 결과가 실제 변경 내용과 일치하는지 수동 검토한다.

## 운영 범위와 한계

- 도구는 커밋 메시지와 PR 텍스트 **초안 생성**을 지원한다.
- Git 커밋을 자동으로 확정하거나 `git push`, GitHub PR 생성 API를 통해 원격 저장소에 자동 반영하는 기능은 과제 범위에 포함하지 않는다.
- AI는 diff만으로 변경 의도나 테스트 결과를 정확히 추론하지 못할 수 있다. 실행하지 않은 테스트를 통과했다고 쓰거나, 실제로 구현하지 않은 동작을 설명할 수도 있다.
- 생성된 결과를 그대로 적용하지 말고 코드 변경과 대조해 검토한다.

### 적용 전 검토 체크리스트

- [ ] 커밋 제목이 실제 변경을 정확하게 요약하는가?
- [ ] PR의 Why/What 설명이 실제 목적과 변경 사항에 부합하는가?
- [ ] How to Test에 실제로 실행할 수 있는 테스트 절차가 적혀 있는가?
- [ ] 실행하지 않은 테스트를 통과했다고 주장하지 않는가?
- [ ] 민감정보가 포함되지 않았는가?
- [ ] 제목 길이와 섹션·불릿 형식이 요구사항을 만족하는가?

## 보너스 과제 (선택)

다음은 기본 과제와 별도로 진행할 수 있는 확장 과제다.

1. **실제 저장소에 PR 작성**: 이전 미션 저장소에서 의미 있는 변경을 수행하고, 생성된 커밋 메시지와 PR 초안을 검토해 실제 PR을 작성한다. 제출 시 PR 링크와 AI 초안에서 최종 PR로 수정한 이유를 5~10줄로 정리한다.
2. **팀 컨벤션 커스터마이징**: 커밋 prefix, 스코프, PR 템플릿 등을 정의하고 설정 파일·CLI 옵션·프롬프트 교체 중 한 가지 이상으로 반영한다. 적용 전후 결과를 비교한다.
3. **안전 모드 고도화**: 마스킹 규칙이나 diff 전송 제한을 확장하고, 숫자 기준과 안전 모드 ON/OFF 결과 차이를 기록한다.
